# RL Dual-Model: 出题模型与解题模型协同训练

---

## 1. 总体框架

与离线数据合成（synthesis_design.md）不同，本方案是**在线 RL 协同进化**范式：出题模型与解题模型通过奖励信号相互驱动，无需预先构建静态数据集。

```
                    ┌─────────────────┐
                    │   出题模型 G    │
                    │ (Question Gen)  │
                    └────────┬────────┘
                             │ 生成题目 q
                             ▼
                    ┌─────────────────┐
                    │   题目缓冲池    │  ← 快速过滤（valid + 难度估计）
                    │  Question Bank  │
                    └────────┬────────┘
                             │ 按难度采样
                             ▼
                    ┌─────────────────┐
                    │   解题模型 S    │
                    │ (Solver)        │
                    └────────┬────────┘
                             │ 解答 a
                             ▼
                    ┌─────────────────┐
                    │   奖励函数 R    │
                    └────┬───────┬────┘
                         │       │
                   reward_G   reward_S
                    (出题)     (解题)
```

**两个模型的 RL 目标：**

| 模型 | 奖励信号 | 目标 |
|------|---------|------|
| 出题模型 G | 难度 × 合法性（见 §3）| 出有效的难题 |
| 解题模型 S | 答案正确性 | 做对题 |

---

## 2. 冷启动：Warm-up 是必要前提

**不从零训练**。从数学预训练模型（Qwen-Math / DeepSeek-Math 等）出发，用离线合成数据集（synthesis_design.md pipeline 的输出）做一轮 SFT：

```
预训练模型
    │
    ├─ SFT on 合成数据集（Easy+Medium）→ 解题模型 S₀
    └─ SFT on 合成数据集（出题格式）  → 出题模型 G₀
    │
    ▼
进入 RL 协同训练
```

**为什么必须做 warm-up：**
- 随机初始化的出题模型出的全是格式错误或无意义的题，解题模型无法从中学到任何信号
- ZPD 奖励的两个阈值（§3.2）需要模型已有一定解题基线才有意义
- 跳过这步直接跑 RL 几乎必然训练崩

---

## 3. 奖励函数设计

### 3.1 解题模型奖励（简单）

$$R_S(q, a) = \mathbf{1}[\text{correct}(a, q)]$$

答案正确得 1，否则 0。可用 sympy 做符号等价检验；对证明题走 Lean4（见 §5）。

### 3.2 出题模型奖励：ZPD 约束

核心设计原则：题目必须落在解题模型的**最近发展区,难倒当前解题模型，但更强的参考模型能解。

$$R_G(q) = \underbrace{\delta\bigl(P_S(\text{correct} \mid q) < \tau_{\text{low}}\bigr)}_{\text{难倒当前解题模型}} \cdot \underbrace{\delta\bigl(P_{\text{ref}}(\text{correct} \mid q) > \tau_{\text{high}}\bigr)}_{\text{参考强模型能解}} \cdot \underbrace{\mathbf{1}[\text{valid}(q)]}_{\text{题目合法}}$$

- $P_S(\text{correct} \mid q)$：当前解题模型在 $q$ 上的正确率（多次采样估计）
- $P_{\text{ref}}$：固定参考模型（如 GPT-4o）的正确率，作为"可解性 oracle"
- $\tau_{\text{low}} = 0.3$，$\tau_{\text{high}} = 0.7$（初始值，可随训练动态调整）
- `valid(q)`：轻量合法性检验（见 §4）

## 4. 合法性检验：轻量实时版

Lean4 单题验证需 30s，无法用于在线 RL。实时合法性检验分两层：

| 层级 | 方法 | 延迟 | 用途 |
|------|------|------|------|
| 规则层 | 格式检查、`\boxed{}` 存在、LaTeX 解析 | < 1ms | 立即过滤垃圾输出 |
| 模型层 | 小型判别器（在 MathQ 标注数据上训练）| < 100ms | 近似 valid(q) |

判别器输入：题目文本；输出：合法概率 $\hat{p}_{\text{valid}} \in [0,1]$。训练数据来自离线合成 pipeline 的 ACCEPT / REJECT 标注（Gate 1-4 的结果）。

---

## 5. 两时间尺度：在线快信号 + 离线 Lean 校正

在线奖励信号有噪声（判别器不完美）。引入慢速 Lean 校正：

```
在线（每 batch）:   出题 → 判别器 valid + P_S 失败率 → 即时 reward
                                        ↓
                              积累题目缓冲池

离线（每 N 步）:    从缓冲池抽样 → MathQ-Verify + Lean4 验证
                    → 得到精确 valid 标注
                    → 用于更新判别器（持续训练）
                    → 修正历史奖励估计（importance sampling）
```

两时间尺度的关键参数：$N$（离线校正频率）。$N$ 越小，Lean 的校正效果越强，但开销越大。实践建议：每生成 500 题跑一次离线验证。

---

## 6. 题目缓冲池：解耦生成与训练

完全在线的同步对抗（每步出题→每步训练解题模型）极不稳定。引入**异步缓冲池**：

```
出题模型（异步）
    │ 持续生成候选题
    ▼
缓冲池（按难度桶分组）
  ├── Easy:   P_S ∈ [0.7, 1.0]
  ├── Medium: P_S ∈ [0.3, 0.7]   ← ZPD 区间，优先采样
  └── Hard:   P_S ∈ [0.0, 0.3]   （可能 unsolvable，谨慎使用）
    │
    ▼
解题模型（异步）
    │ 从 Medium 桶优先采样训练
    ▼
定期更新各题目的 P_S 估计 → 重新分桶
```

**缓冲池带来的稳定性**：
- 出题模型和解题模型不再强耦合，各自按自身节奏更新
- 类似 off-policy RL 的 experience replay，平滑训练分布
- 缓冲池大小建议：10k–50k 题，按 FIFO + 质量加权淘汰

---

## 7. 种群训练：防止针对性 exploit

单一解题模型 vs 单一出题模型容易产生"针对性利用"——出题模型学会专门利用解题模型的某个盲点，而不是生成真正困难的数学题。

改为**维护 $K$ 个解题模型的种群**：

$$R_G(q) \propto \frac{1}{K} \sum_{k=1}^{K} \bigl(1 - P_{S_k}(\text{correct} \mid q)\bigr) \cdot \mathbf{1}[\text{ZPD}(q, S_k)]$$

- 出题模型的奖励基于对**平均解题能力**的挑战，而非某一特定模型
- $K=3$–$5$ 即可，代价可控
- 种群中不同模型可在不同领域（代数 / 数论 / 几何）专精，出题模型被迫覆盖多个领域

## 8. 训练稳定性：关键超参数与防崩措施

| 风险 | 症状 | 缓解方法 |
|------|------|---------|
| 出题模型 reward hacking | 生成格式合法但内容无意义的"伪难题" | ZPD 双约束 + 参考模型过滤 |
| 解题模型过拟合缓冲池 | 在缓冲池题上 acc 高但在新题上差 | 定期引入 MATH / AMC 原题混合训练 |
| 两模型进化速率不匹配 | 一方远快于另一方导致退化 | 分别设 RL learning rate；慢的一方降低更新频率 |
| 题目分布坍缩 | 出题模型只出某类题 | 多样性惩罚：$-\lambda \cdot \text{sim}(q, q_{\text{recent}})$ |
| 合法性判别器失效 | 出题模型学会骗判别器 | 离线 Lean 校正持续更新判别器（§5）|

---

## 9. 与离线合成方案的关系

两个方案**互补而非互替**：

```
离线合成 pipeline（synthesis_design.md）
    │
    ├─ 产出高质量静态数据集
    ├─ 为 RL 双模型提供 warm-up 数据
    └─ 为合法性判别器提供训练标注
    │
    ▼
RL 双模型（本文档）
    │
    ├─ 在离线数据基础上进一步强化
    └─ 自动生成超出离线数据分布的极难题
```

**推荐路线**：先完成离线合成，训练出基线模型，再以此为起点探索 RL 双模型。

## 10. 开放问题与研究方向

| 问题 | 现状 | 研究价值 |
|------|------|---------|
| $\tau_{\text{low}}$、$\tau_{\text{high}}$ 如何动态调整？ | 固定阈值，粗糙 | 自适应 ZPD 边界 = 新贡献 |
| 合法性判别器的泛化性？ | 在离线数据分布内可靠，out-of-distribution 未知 | 判别器 + Lean 协同校正 |
| 出题模型的输出是否仍需知识图谱约束？ | 目前无 | 将 DAG 结构注入 G 的生成策略（hybrid 方向）|
| 如何评估协同进化的质量？ | 尚无标准指标 | 新 benchmark：ZPD coverage + Elo rating |
